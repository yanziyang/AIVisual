About this demo

PROMPT / IMPLEMENTATION / SOURCE

Original prompt

Create a single-file HTML/JS interactive 3D web application demonstrating a single car being assembled in a factory.

Implementation details

One self-contained file
HTML, CSS, and JavaScript are embedded together. No external libraries, models, fonts, or network requests are needed to run the demo.
Custom WebGL scene
The car, robot arms, conveyor, and factory fixtures are built from procedural 3D geometry. GLSL shaders provide lighting, highlights, and distance fog; layered shapes create contact shadows.
Six-stage assembly animation
A 48-second timeline drives the chassis, powertrain, interior, body, wheels, and finishing stages. Smooth interpolation moves parts into place, while articulated robot arms follow the current stage.
Interactive controls
Play, pause, replay, scrub, or jump to a stage. Adjust playback speed and paint color. Drag to orbit, scroll or pinch to zoom, and reset the camera. The layout adapts to mobile screens and respects reduced-motion preferences.

WebGL vs. Three.js

Three.js sits on top of WebGL. WebGL is the browser’s graphics API; Three.js provides objects such as scenes, cameras, meshes, and materials, and handles much of the rendering work. Its WebGL renderer uses WebGL underneath. Three.js documentation

The choice depends on the project:

ConsiderationDirect WebGLThree.js
Best fitSmall, specialized renderers or learning graphicsMost interactive 3D applications
DevelopmentWrite shaders, matrix math, and rendering infrastructureStart with existing scene and rendering tools
Visual featuresImplement each feature yourselfBuilt-in support for materials, lighting, and shadows
MaintenanceMore custom code to maintainLess rendering infrastructure to maintain
PerformanceFine control, but requires careful optimizationOften sufficient; still needs scene optimization

Why this demo uses direct WebGL: the geometry is simple, and the implementation prioritizes a self-contained file with no dependencies.

The single-file requirement did not require that choice. Three.js can be bundled into the HTML and run offline too. Direct WebGL also isn’t automatically faster.

For a version that will grow, Three.js would be the preferred choice. Realistic car models, better materials, shadows, and more complex animation would benefit from its existing tools, leaving more effort for the factory experience and less for maintaining a renderer.
